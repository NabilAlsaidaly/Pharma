### ظهور الفئات والعلاقات بدقة

اسم/وصف الفئة الملتقطان داخل إصدار المقال لا يتغيران بمجرد تعديل الفئة؛ إعادة نشر المقال تلتقط النص الجديد. فحص حالة الفئة الحالية يحجب بيانات الفئة المخفية فوراً من المقال مع بقائه منشوراً. دليل الفئات يعرض بيانات الفئة الحالية المرئية؛ لا عدد مقالات افتراضي أو إحصاء يخلط مسودات ومنشوراً. استعادة فئة لا تنشطها ولا تنشر أي مقال. يمكن الاحتفاظ بفئة قديمة مخفية عند إعادة النشر مع تحذير، لكن اختيار فئة جديدة يتطلب ظهورها.

عضوية Products/Concerns وترتيبها ثابتان للإصدار؛ بيانات الرابط المعروضة (id/name/slug ، وحالة توفر Product فقط) تأتي من إسقاط Catalog الحالي الظاهر، لا من اسم مخفي مخزن احتياطياً. لا أسعار أو صور أو وصف طبي أو قائمة Variants في الروابط المختصرة. لذلك قد يتغير الاسم/slug العام عند تحرير Catalog ، دون تغير نص/عضوية المقال؛ هذا مقصود لتبقى هوية Catalog مرجعية. المالكة تستطيع رؤية التاريخ الخاص والعلاقات المحفوظة لإصلاحها، دون تسريبها للعامة.

### 9.1 تجربة التحرير وحدود التنسيق

المقترح محرر كتل صغير داخل Owner Blade الحالي، بلا مكتبة WYSIWYG أو اعتماد جديد. تضيف المالكة «فقرة»، «عنوان فرعي»، «قائمة نقطية»، «قائمة رقمية» أو «صورة توضيحية»، وتحرك الكتلة لأعلى/أسفل أو تحذفها. حقول النص تحفظ الأسطر العربية؛ أزرار عريض ومائل ورابط تطبق على النص المحدد، مع إزالة التنسيق ومعاينة آمنة. القوائم لها إضافة/حذف/ترتيب عناصر. لا إدخال JSON أو رموز Markdown أو UUID أو HTML يدوياً. رفع الصورة ثم اختيارها من صور المقال في موضعها داخل المتن، مع تنبيه عند مغادرة تعديلات غير محفوظة.

الحد الأدنى المقترح للتنسيق الأساسي **عريض ومائل فقط**، ويمكن جمعهما على المقطع نفسه. عنوان المقال الرئيسي يُعرض h1 من title؛ العناوين الداخلية h2 أو h3 فقط. القوائم مستوى واحد، والترقيم يبدأ 1؛ لا قوائم متداخلة أو ترقيم يبدأ بقيمة مخصصة. الصور كتل مستقلة بعرض العرض المتاح، دون التفاف حول النص أو أعمدة أو أبعاد يحددها المحرر. لا ألوان أو أحجام خطوط أو CSS أو جداول أو فيديو أو iframes أو scripts أو HTML خام. هذه حدود مقصودة للمحرر الأول، وليست وعوداً بقدرات محرر مكتبي كامل.

### 9.2 تمثيل المحتوى وتخزينه

داخل صف `educational_article_revisions` يكون `body_document` عمود JSON مضبوطاً وذا إصدار، مثلاً:

```json
{
  "schema_version": 1,
  "blocks": [
    {"type": "heading", "level": 2, "runs": [{"text": "عنوان فرعي", "bold": false, "italic": false, "href": null}]},
    {"type": "paragraph", "runs": [{"text": "فقرة توضيحية.", "bold": true, "italic": false, "href": null}]},
    {"type": "list", "style": "unordered", "items": [
      [{"text": "عنصر أول", "bold": false, "italic": false, "href": null}],
      [{"text": "مصدر اختارته المالكة", "bold": false, "italic": true, "href": "https://example.org/reference"}]
    ]},
    {"type": "image", "media_id": "01999999-0000-7000-8000-000000000001", "caption": "شرح اختياري للصورة"}
  ]
}
```

هذا **مثال بنيوي اصطناعي، لا مقال أو مصدر أو صورة فعلية تُزرع في النظام**. `ordered` هو البديل الوحيد لـ`unordered`. كل run مقطع نصي يملك text وعلمَي bold/italic ورابطاً اختيارياً؛ لا marks أو attributes أو عقد قابلة للتوسعة الحرة. يُرفض HTML المدخل داخل text/caption/alt كما في نموذج الأمان الحالي، مع حفظ العربية وعلامات الترقيم وفواصل الأسطر المشروعة. التطبيع يثبت مفاتيح البيانات ويجمع المقاطع المتجاورة متطابقة التنسيق دون تغيير الكلمات أو معنى الفقرات.

الحدود الإضافية المقترحة للمستند: حتى 100 كتلة إجمالاً، وحتى 50 عنصراً للقائمة، وحتى 20 مقطعاً لكل فقرة/عنوان/عنصر قائمة، ومجموع النص المرئي≤40000 محرف شاملاً تعليقات الصور. caption≤500 و alt≤250. JSON المطبع بترميز UTF-8 دون ASCII escaping حتى 192KiB؛ يظل حد طلب الحفظ الكلي 256KiB، والرفع 10MiB بصورة واحدة في الطلب. تجاوز الحجم البنيوي يرفض 422، وتجاوز حد HTTP يرفض 413. تُستخدم نماذج multipart لتجنب تضخم ترميز النص العربي كـ URL؛ لا تزداد حدود HTTP المعتمدة. يمكن حفظ مستند فارغ للمسودة، لكن نشر مستند صور فقط دون نص غير فارغ مرفوض وفق شرط المتن السابق.

هذه الحالة تبرر JSON ضيقاً لبنية عرض محددة؛ لا يحل محل جداول المقال والفئة والنشر والتدقيق والمراجع وعلاقات Catalog أو الصور. لا تُخزن نسخة HTML ثانية أو متن plain-text ثانٍ يتعارض معه. البحث المعتمد يبقى في title/excerpt فقط؛ لا بحث JSON أو محرك بحث جديد. إصدارات المقال تحفظ body_document كاملاً غير قابل للتعديل، و schema_version يخص صيغة المستند ويختلف عن revision الذي يخص نسخة المقال. إدخال schema_version غير مدعوم يُرفض بدلاً من التخمين. أي تغيير بنيوي لاحق يحتاج عقداً جديداً مع إبقاء قراءة الإصدارات القديمة.

### 9.3 الروابط الآمنة

href اختياري وحتى 2048 محرف. المقترح **HTTPS مطلق فقط** دون بيانات دخول أو منفذ مخصص أو تحكم أو backslash أو مخطط آخر؛ لا javascript/data/file ولا protocol-relative ولا HTML كوجهة. يعاد استخدام منطق التحقق التقني الحالي أو محول ضيق مماثل دون تعديل عقود 6E. لا جلب أو معاينة بعيدة أو تحقق DNS أو فحص سريري/علمي؛ قبول صيغة URL لا يثبت موثوقية الموقع. الروابط الداخلية النسبية ليست ضمن النسخة الأولى لتجنب افتراض مسارات Next.js لم تُبنَ بعد. روابط Catalog التحريرية المعتمدة تبقى العلاقات المنظمة الآمنة؛ href المكتوب في المتن ليس بديلاً عنها ولا ينشئ علاقة أو توصية آلية.

Laravel يتحقق قبل التخزين ومرة أخرى ضمن صلاحية النشر. عارض Next.js يربط href بالحقل المتحقق منه في عنصر a ثابت، ويفضل نفس النافذة؛ إن اختار فتح نافذة جديدة يلزم rel="noopener noreferrer". لا تمرير props/style أو أسماء عناصر ديناميكية من البيانات. لا توليد HTML في API ولا استخدام dangerouslySetInnerHTML.

### 9.4 هويات الصور وعلاقتها بالإصدارات

الغلاف اختياري وعدده 0..1، والداخلية 0..5 صور مختلفة؛ الحد الكلي 6 صور **للإصدار الحالي** وليس لكل تاريخ المقال. لكل ملف media UUID يولده الخادم ومالك Article ومسار خاص ثابت وهضم وأبعاد بعد المعالجة. علاقة خاصة بكل إصدار تحفظ media_id ودور cover/inline و alt لذلك الإصدار؛ ترتيب الصور الداخلية و caption يأتيان من كتل المستند. لا تخزين لمسار أو URL يقترحه العميل داخل المستند.

مقترح الجداول التقنية: `educational_media` لهويات الملفات الخاصة بالمقال، و`educational_revision_media` لعضويتها وبياناتها في الإصدار. مفاتيح خارجية مقيدة ومركبة تمنع ربط صورة بمقال آخر وتضمن انتماء الإصدار للمقال نفسه، وفرادة تمنع تكرار الصورة في الإصدار. مواضع محدودة تحفظ حدود الدور (cover واحد و inline حتى 5). تفاصيل قيود SQL النهائية تُختبر على MySQL، وليست مثبتة بمجرد هذا الوصف.

media_id داخل JSON لا يقبل FK مباشراً؛ لذلك تتحقق أوامر Laravel ذرياً من تطابق كل كتلة صورة مع علاقة inline في **الإصدار نفسه**، ومن عدم التكرار أو انتحال صورة/مسار. جدول العضوية المرجع العلاقي للتفويض، والمستند يحدد العرض فقط. يمكن للمسودة الاحتفاظ بصور داخلية مرفوعة لم توضع بعد مع تنبيه؛ النشر يشترط وضع كل صورة inline محتفظ بها مرة واحدة، أو إزالتها من المسودة، دون حذف الملف التاريخي. صورة الغلاف لا يعاد استخدامها كداخلية في الإصدار نفسه. الحذف من المتن أو إعادة ترتيبه لا يحذف صورة من نسخة منشورة سابقة؛ إزالة الصورة من قائمة المسودة تتطلب إزالة كتلتها في أمر متسق أو تُرفض 422.

التعديل في alt أو caption أو الموضع أو استبدال الملف يصنع إصداراً جديداً؛ لا يغير bytes أو بيانات الإصدار المنشور. تُرفع صورة واحدة في العملية ثم توضع في المتن؛ يسمح بتكرار العملية حتى 5 داخلية. المصدر 5MiB،≤4096 لكل بعد،≤4194304 بكسل،GD decode/re-encode إلى PNG≤8MiB،تحقق المحتوى،إزالة metadata،رفض SVG والملفات غير المسموحة. لا صورة بعيدة أو نسخ تلقائي من Catalog،ولا byte في JSON. التحضير خارج أقفال SQL،وملفات خاصة بأسماء خادم ثابتة،وتعويض الملف الجديد عند فشل SQL والاحتفاظ بالتاريخ؛خطر orphan عند الانهيار مستمر وموثق.

المعاينة الخاصة تسمح للمالكة بصور مسودات وتاريخ هذا المقال مع guard/revocation/no-store. API العام لا يعيد إلا الغلاف والصور المستخدمة في الإصدار المنشور الحالي لمقال غير مؤرشف. endpoint الصورة يتحقق من تلك العضوية؛ معرفة UUID لا تكفي. غلاف/صورة استُبدلت ولا تزال في النسخة المنشورة القديمة تبقى عامة حتى إعادة النشر؛ بعده تصبح 404 إذا لم تعد ضمن النسخة الحالية. إلغاء النشر أو الأرشفة يحجب كل صوره العامة؛الاستعادة لا تعيدها دون نشر. الرد المقبول سابقاً لا يُسترجع بأثر رجعي.

### 9.5 عقد Laravel API المقترح لعرض Next.js

لا endpoints جديدة فوق الخمسة المقترحة؛ بيانات قائمة المقالات لا تحمل body أو الصور الداخلية، وتحمل cover اختيارياً فقط. تفاصيل المقال تعيد الإسقاط المنشور المتسق، ومعه:

```json
{
  "success": true,
  "data": {
    "slug": "example-article",
    "title": "مثال بنيوي للمقال",
    "revision": "7",
    "body_format": "structured_blocks",
    "body": {
      "schema_version": 1,
      "blocks": [
        {"type": "paragraph", "runs": [{"text": "نص من المالكة", "bold": false, "italic": false, "href": null}]},
        {"type": "image", "image": {
          "id": "01999999-0000-7000-8000-000000000001",
          "url": "https://backend.example.test/api/v1/education/media/01999999-0000-7000-8000-000000000001.png",
          "alt": "وصف الصورة من المالكة",
          "width": 1200,
          "height": 800
        }, "caption": null}
      ]
    },
    "cover": null
  }
}
```

هذا **مقتطف توضيحي للحقول الخاصة بـC/D**، لا الاستجابة الكاملة ولا حقيقة منشورة. بقية حقول الفئة والعلاقات والمراجع وSEO والتواريخ وenvelope تُحسم في توثيق التنفيذ وفق القرارات المعتمدة. Laravel يحول media_id الداخلي إلى image آمن داخل الكتلة من عضوية الإصدار نفسه؛ لا مسار قرص أو Owner ID أو بحث في نسخة أحدث. cover عند وجوده له id/url/alt/width/height نفسها. أبعاد الصورة يحددها الخادم بعد GD؛ لا أبعاد من العميل.

عارض Next.js المستقبلي عملية عرض محددة: paragraph→p، وعنوان بمستوى2/3→h2/h3، وقائمة بنمط محدد→ul/ol مع li، وصورة→figure/img/figcaption، ومقاطع نصية→text مع strong/em/a المسموحة. يهرب React النصوص بطبيعته؛ لا innerHTML أو Markdown parser. واجهة العرض لا تختار صورة من التاريخ أو تعيد تقييم النشر أو التصنيف أو روابط Catalog أو المراجعة الصحية. جميع تلك القرارات ومصدر الصورة ومحتوى الإصدار تأتي من Laravel. التعامل مع schema غير مدعوم يكون خطأ عرض واضحاً، لا تخميناً لتنسيق أو سياسة. معاينة Owner تستخدم المخطط نفسه لكن بروابط صور خاصة مأذونة.

هذه وثيقة عقد لهذين التعديلين فقط؛ لا تنفيذ Next.js أو التسليم النهائي الموحد المؤجل. الاختبارات اللاحقة تشمل حدود الكتل والقوائم والمقاطع والروابط، وXSS والحقول الغريبة، وانتحال media_id، وتطابق الإصدار وصوره وalt، وصوراً مفقودة أو غير موضوعة أو مكررة، ومزيج النص والصورة تحت سباقات الحفظ والنشر والإلغاء والتعويض، وعرض النموذج العربي ولوحة المفاتيح.
