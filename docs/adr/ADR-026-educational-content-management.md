# ADR-026 — Versioned educational content inside Content

Status: accepted for implementation following explicit Owner approval of the [complete gate](../reports/phase-06g-educational-content-design-gate.md), including revised C/D section9, on2026-10-17. Number026 verified unused at baseline a78f4149e1a68342e318405f8d25c4347a4cd29b.

Content owns a focused educational slice with first-class Article/Category commands, immutable revisions, revision-specific Catalog/source/media relationships and attributed SQL audit. Existing ContentTypes/RevisionedStore contracts for banners/pages/FAQs/policies remain intact. Narrow BusinessRaster preparation is reused; Gifts and Catalog business commands are not repurposed as Article mutations.

Body uses a strictly validated schema1 JSON presentation document: paragraphs, h2/h3, single-level ordered/unordered lists, bold/italic/HTTPS text runs and up to five inline image blocks. JSON contains no publication authority, paths, arbitrary attributes or business relationships. Media identities and revision membership have restrictive composite foreign keys; commands atomically validate JSON image references against those rows. Optional cover plus five inline images, explicit alt, immutable private bytes, isolated history and publication-pointer authorization. The approved gate defines all text/count/body limits. No HTML storage/rendering, Markdown parser, editor dependency or remote fetch.

Owner revalidation/shared row lock → exclusive per-Owner educational coordination row → durable operation replay → Article → Category → sorted Products → sorted Brands → sorted Concerns → revision/children/publication/audit. Category commands stop at Category, never reverse to Article. Image decoding occurs before locks. Immutable current-revision reads and batched live Catalog projections use a coherent RR read boundary. Hidden Catalog/category references are suppressed while Article remains published. Previously admitted responses cannot be recalled.

The first real Catalog concurrency run exposed two retries. Actual InnoDB deadlock evidence showed Article holding Owner X while waiting for Concern X, and Catalog holding Concern X while waiting for Owner S: the Catalog audit foreign key introduces an implicit lock edge. The original Owner-X sketch was therefore replaced with Owner S (still prevents credential/status changes during admission) and a separate `educational_owner_locks` row X (still serializes all editorial operations and operation identities). Catalog Owner-S FK checks are compatible; Catalog never touches the educational coordination row. This additive technical table changes no business policy or legacy Catalog writer. Tests verify the actual independent transactions and attempts, including first-time coordination creation; no universal deadlock-free claim.

Article draft changes never alter the existing published document, image metadata, memberships or editorial requirements. Publication requires the approved explicit general/health_related classification, review acknowledgment and, for health_related, source plus additional acknowledgment. Software records Owner actions and validates syntax; it does not certify clinical truth, invent sources/authors/disclaimers or publish generated advice. Article relationships do not mutate Catalog or imply medical suitability.

Laravel APIs return safe published structured blocks and server-resolved image descriptors; future Next.js performs fixed component rendering only. Existing Owner authentication/CSRF/revocation/private prefix, API envelopes and no-store remain. No Next.js implementation, development/production migration, deployment, real Owner provisioning, PR merge or Phase6H.
