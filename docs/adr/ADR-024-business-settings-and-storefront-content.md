# ADR-024: Typed business configuration and versioned storefront content

Status: accepted for Phase6E implementation, pending Owner PR review. Number024 verified unused on starting main7427c8a7032973792e0cd77f2a2abaa07157ab78.

The Owner explicitly approved [the consolidated gate](../reports/phase-06e-business-configuration-design-gate.md) on2026-10-16: «أعتمد المقترح كاملاً مع تأجيل إيقاف الاستقبال».

Settings owns typed store identity/contact/social, currency presentation, immutable preparatory payment policy revisions and delivery zone/fee preparation. Content owns first-class banner/page/FAQ/policy records and immutable revisions. Separate explicit SQL tables per bounded entity, not arbitrary keys/EAV or an application-configuration JSON blob. A small shared RevisionedStore coordinates SQL/version/audit only; fixed domain catalogs supply fields and validation. Separate private controllers and command adapters retain module ownership. Payments/Delivery execution and Orders admission remain unchanged.

Each aggregate has a latest draft and nullable composite-FK current published revision pointer. Every successful save/media/publication/archive/restore makes an immutable version and attributed event atomically. New draft edits never rewrite the public revision. Explicit confirmed publication, no scheduling; archive clears publication, restore stays unpublished. Stable slugs are reserved for the document's lifetime to prevent a draft rename freeing a still-public URL. Pages/FAQ/policies are bounded plain text, never arbitrary HTML/legal templates. Only Owner-supplied policy text is publishable.

Single active Owner row→operation replay lookup→target row is the consistent lock order for all new writes. This serializes initial singleton creation, different target operations reusing an operation UUID and competing tab edits. It deliberately serializes this Owner's settings/content writes; no production throughput claim. Customer services do not lock this Owner row; new services never acquire Customer/Cart/Catalog locks. Expected string-safe unsigned versions reject stale edits; canonical Owner-operation fingerprints replay before stale validation. Real independent-process races verify behavior.

Secure GD re-encoding occurs before SQL locks; immutable private-local-disk generated files and prior references are retained, fresh paths compensated on SQL failure. Existing Owner authorization protects binary previews. A narrow public media read admits bytes only when an unarchived aggregate's current published revision references that path, using one statement snapshot before streaming. Draft/replaced/unpublished bytes return404 even with a known public URL. No draft metadata/preview endpoint is public. SQL/filesystem crash atomicity and orphan reconciliation remain limitations.

Public APIs add only explicit published informational projections with live SQL/no-store, no drafts/commercial preparations/audit/secrets/Customer data. Missing schema503, absent/unpublished document404, honest null/empty states. USD/SYP remain independent; full100%/deposit0.01–99.99% and nullable/explicit-zero delivery fees are prepared only, no prices/totals/financial snapshots/execution. PAY-001 unchanged. Intake pausing entirely deferred by explicit approval. No dependencies, Redis, Next.js, System Console, real provisioning or development/production migration. One PR remains open/unmerged; deployment is separate.
