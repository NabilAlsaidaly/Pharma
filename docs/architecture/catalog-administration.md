# Catalog administration

Phase6C extends the existing custom Owner Blade portal; no second application, packaged admin, staff RBAC, storefront, Redis or System Console changes. [Design gate](../reports/phase-06c-catalog-write-design-gate.md), [ADR022](../adr/ADR-022-catalog-administration.md), [web forms](../api/owner-catalog-web.md), [schema](../database/catalog-soft-delete-and-audit.md), [security](../security/catalog-administration.md).

## Write boundary

Catalog/Application/Administration owns explicit record writes, structural ownership, archival/restore, media coordination, fixed typed bulk actions and audit coordination. Catalog Infrastructure retains authoritative Eloquent setters/locks. OwnerCatalogController and FormRequest are the private web adapter, using existing RequireOwner/owner guard. ManagementDashboard remains a read-side projection and never mutates business tables. Seven focused classes plus the meaningful fixed resource registry avoid a universal SQL editor.

Product attributes follow existing schema, including optional descriptions/usage/benefits/suitability/recommendation and independent USD/SYP. New Products remain hidden/unavailable unless explicitly selected otherwise. Brand/Concern/Variant ordering uses existing sort_order; Product has no invented stock/type/order column. Omission preserves fields, explicit nullable empty input clears, blank edit slug preserves established URL. Generated new slugs use readable transliteration plus random suffix; database unique index is final authority, and archived slugs remain reserved.

## P1/C2/V1/S1

All physical Variants, including archived, reserve Variant-owned pricing. Product persistence checks physical existence with a locking current read under the Product lock. Clear parent prices explicitly before first Variant. No reassignment, automatic clearing/copying, parent/Variant conversion, inheritance, floating money or conversion. CatalogPrice and existing price setters preserve DECIMAL(18,2) strings/null/zero. Visible null/zero prices remain informational and do not authorize admission.

Declared Product/Variant availability remains independent; unavailable dominates then on_request. Product/Brand must both be active and unarchived to be publicly visible. Concern archival/hiding does not hide Product. Eloquent scopes exclude archived entities; raw management joins/subqueries explicitly exclude deleted_at. Current Product counts are separate from archived; Customer/preliminary-request counts are unchanged. Structural selection count includes archived Variants while selected Variant lookup excludes archived ones, so all-archived Variant products cannot accidentally admit a direct-price selection.

## Transactions and stale edits

Short retryable transactions lock ordered Products first, then child Variants/Images, then referenced Brands/Concerns. Brand-only writes acquire no Product/Customer/Cart afterwards. Customer-first admission retains its existing Product/Variant/Brand lock order. No admin operation locks Customers or Cart. Overlapping bulk operations lock the entire bounded set in stable order before validating versions/applying changes. Association sync locks existing/new Concern rows after the Product. Restrictive FKs remain unchanged.

lock_version is required on edits and checked under row lock; stale tabs receive Arabic409. Retry is not used as a substitute for stale-edit detection. Version changes and audit insert commit with business SQL. Bulk previews bind exact IDs/versions/action/filter set to one expiring server-side confirmation (10minutes), capped100; matching filters are re-resolved with locks at execution, and changed sets fail atomically. Individual or page selection uses IDs; all-matching is a distinct explicit scope. Clear/history/page navigation resets selection; no browser storage. A broad synchronous operation over100 must be narrowed; no background/unlimited promise.

## Archival/restore and media

Products, Brands, Concerns, Variants and Images use SoftDeletes. Preserve UUID/status/slugs/FKs/pivots/Customer selections/request facts, no cascades or purge. Archived Brand blocks Products without changing their status. Product can restore under archived Brand as non-public; child restore requires active parent. All physical Variants preserve price ownership even while archived. Image archive clears explicit primary before soft deletion; restore requires safe existing bytes and returns secondary. Existing generated unique primary key is unchanged. Primary assignment is atomic under Product lock; fallback remains deterministic.

Uploads use GD inspection/decode/re-encode to PNG outside the transaction, max5MiB input,4096 per dimension/4,194,304pixels,20 current Product images and8MiB Owner Catalog body. JPEG/PNG/WebP/GIF supported when GD decoder supports them; animation/metadata are intentionally flattened. SVG/unsupported/corrupt/mismatched/executable names and unsafe paths rejected. Generated immutable public-disk paths only. Old image/logo bytes are retained; new file write failure creates no SQL pointer, later SQL failure compensates only fresh path. Crash between file write and commit can orphan files; failed cleanup is correlation-only logged, no distributed atomicity or cleanup worker. Production GD/public disk/symlink/permissions/limits and separate schema rollout remain operational prerequisites. Browser/test storage is isolated, not production media.

## Compatibility

Favorites/Cart retain rows; blocked selections still permit existing decrease/removal. Preliminary checkout locks/revalidates current Catalog before new submission; idempotent replay and immutable contact/selection IDs remain unchanged. No audit data is exposed publicly. Existing response envelopes and PAY001 remain. Native JS only adds explicit bulk selection semantics; existing menu, dashboard, search and identity remain. Production load, full assistive technology and environment rollout need separate verification.

FIX-6C-001 reproduced a public serialization inconsistency: one archived physical Variant yielded current count0 and pricing.source=product while internal selection remained Variant-owned/blocked. Public Catalog and Favorites now share the explicit Product SQL EXISTS pricing-ownership projection; Resource uses physical existence, while current counts/lists/ranges retain SoftDeletes. With all Variants archived, source remains variants, both direct prices and range endpoints remain null; no archived selection is exposed. Six regression tests cover direct/current/mixed/all-archived/restored states, every ProductResource path, retained Cart/immutable Checkout and bounded SQL. No write/admission policy or schema change.
