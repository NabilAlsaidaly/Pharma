# Article publication, structured content and revisions

Actions: save, media, publish, unpublish, archive, restore. Each successful command creates exactly one immutable revision and attributed event atomically. Save may omit body/scope/relationships/images but needs a meaningful title and stable slug on initial identity. A valid empty body is `{schema_version:1,blocks:[]}`. No autosave publication. Publish validates exact expected version, unarchived state, readable text, explicit general/health_related, review consent, required health sources/extra consent, all current image memberships/alt/files, and structured syntax. Image-only documents cannot publish.

The Article published pointer references its own `(article_id,version)` via restrictive composite FK. Latest draft and current publication may differ. Every body/category/media/link/source/featured/order mutation stays private until explicit publication. Unpublish/archive clears publication. Restore stays unpublished. Slug remains owned for life, including archive. Category hide/archive suppresses only the category projection and scoped route, not Article publication. Its saved label changes only when the Article is republished; Category directory uses current visible labels.

Schema1 body JSON is tightly scoped immutable presentation data, not a generic business blob. Block types: paragraph(runs), heading(level2/3,runs), list(style ordered/unordered,items of runs), image(media_id,nullable caption). Each run has text, strict boolean bold/italic and nullable absolute HTTPS href. No HTML, arbitrary attributes, nesting, embeds, colors or Markdown. Normalize adjacent equal-mark runs without inserting spaces; preserve legitimate Arabic/Unicode/line breaks. No HTML copy or alternative plain-body truth is stored. Title/excerpt search avoids JSON scans.

Limits:100blocks,50items/list,20runs/text region,40000visible Unicode characters including captions,5distinct inline images,caption500,alt250,href2048,canonical UTF-8 JSON192KiB. HTTP save256KiB overall, media10MiB with one source5MiB. Text fields and all metadata together must fit the aggregate limit. Owner form uses multipart to avoid percent-encoding growth; invalid shape/unsupported schema/unknown fields fail422, oversized HTTP413. Draft can retain unplaced internal images with warning; publication requires each retained inline image exactly once and no dangling image blocks.

OwnerS revalidation → own per-Owner coordination rowX (atomic upsert) → current locking durable replay → ArticleX → CategoryX → ProductsX ordered → BrandsX ordered → ConcernsX ordered → revision/children/pointer/event. Category stops after Category, never Article. OwnerS blocks revocation/password/status changes while admitted commands run and remains compatible with Catalog audit FK OwnerS. Initial OwnerX design produced an actual InnoDB deadlock under Catalog races; [ADR026](../adr/ADR-026-educational-content-management.md) records the evidence-driven correction. Retry3 remains for transient deadlocks, not stale overwrites. Global Owner+operation uniqueness within this educational slice serializes cross-target operation identities.

Fingerprints include normalized target/action/version/values/children/review/health/media digest. UUIDv4/v7 operations lowercase, versions canonical unsigned decimal strings; MAX may be read but not advanced. Identical committed retry returns original target after current Owner authorization before stale/current eligibility checks; changed operation payload409. A replay may not use revoked credentials. Read requests never create coordination rows/events/publication.

Detail reconstruction/public projection uses an RR transaction so header/body/relationships share a committed snapshot. Page and count can span concurrent publication timing; no draft mixing within a returned row. Already admitted/serialized responses cannot be recalled after unpublication. Publication checks file existence under short SQL transaction, while GD decode/re-encode occurs before locks. Retained bytes/history grow; SQL/filesystem crash atomicity and production throughput are not claimed.
