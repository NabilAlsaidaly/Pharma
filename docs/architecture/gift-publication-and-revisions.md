# Gift publication and revisions

gift_packages holds immutable ID/slug, latest lock_version, nullable published_version, archival and timestamps. Every save/media/publish/unpublish/archive/restore inserts a new immutable typed revision and its complete relational children, within one transaction. No mutable child set shared between draft and publication. Composite published FK enforces same-package/version. Slugs never change/release. Restore is unpublished; old versions/files are retained, no physical deletion endpoint.

Publication requires meaningful name, available/on_request package state,1–50 valid components, positive price in at least one currency,1–10 safe existing images with nonempty alt text, and active associated occasions. Package/metadata/children/pointer/audit commit together. Draft modifications and image removals preserve the old publication. Current Catalog names are refreshed into a new publication; old publication text stays stable after renames. Catalog image edits never automatically replace Gift-owned uploaded images.

Public query joins exact current revision and uses SQL NOT EXISTS invalid Catalog component before pagination. Physical Variant existence prevents archive-to-parent fallback. Public list does not hydrate component history; only detail loads bounded current components. A published package can lose current eligibility and be withheld without destroying its pointer. Restored Catalog eligibility restores visibility unless Owner explicitly unpublished/archived. Positive selected-currency price is separate from public visibility; a published package may show currency_price_unavailable after publication in another currency.

Observed EXPLAIN initially materialized invalid components across historical revisions. The final MySQL-specific fixed STRAIGHT_JOIN starts with current Package pointers, then unique current-revision lookup; NO_SEMIJOIN() keeps the component eligibility probe dependent on that revision. The fixed server-owned SQL fragment survives paginator COUNT and media EXISTS clones, contains no caller-selected SQL, and preserves the eligibility predicate. Real page/count EXPLAIN tests reject unrelated revision/component scans or materialization. These controls follow the primary [MySQL join reference](https://dev.mysql.com/doc/refman/8.4/en/join.html) and [optimizer hints reference](https://dev.mysql.com/doc/refman/8.4/en/optimizer-hints.html); target engines are local9.7 and CI8.4. Sorting current eligible packages may still require a filesort; no production throughput claim follows from this plan.

Gift media stays on private local disk at server-generated gifts/{uuid}.png. Public binary admission uses the same published-package SQL eligibility plus a current revision image reference in one SQL statement; Owner preview accepts any retained Gift revision image after Owner authorization. No raw private-disk URL or storage path appears in public metadata. Known draft, removed-from-current-publication, unpublished, archived or Catalog-ineligible media returns404 unless another eligible current publication legitimately references the same asset. Application commands never attach another package's media through client-supplied IDs.

SQL/filesystem crash may leave orphan files; no janitor/retention promise. Fresh paths are compensated on SQL failure and reused across retries; old bytes retained. GD preparation precedes locks. Bounded file writes/existence checks during mutation are documented; no image decoding or response rendering/streaming under SQL locks. Admission ends before streaming; later unpublication cannot retract already-admitted bytes. no-store is not retroactive remote-cache erasure.
