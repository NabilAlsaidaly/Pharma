# Preliminary request management

See [accepted workflow gate](../reports/phase-06d-review-workflow-design-gate.md) and [ADR023](../adr/ADR-023-preliminary-request-review.md). Orders/Application/Review owns commands and bounded bulk coordination; Domain/Review owns the approved transition matrix; Infrastructure/Persistence owns review/event records and safe Owner projections; Interfaces/Http/Owner is the protected web adapter. ManagementDashboard consumes read-only review metrics, never business writes. Existing owner.requests.index/show remain the sole request workspace.

Original submission status remains submitted. A missing review is inferred new/version0; GET creates nothing. Genuine note/follow-up/transition creates the aggregate, increments version, inserts one durable event atomically. Notes do not begin a review. State changes record first review-start, current completion and last state-changing Owner; reopen clears current completion time while earlier event remains. All actual events advance last activity. Author IDs remain stable, current display names are joined in one query without credentials.

Allowed new→under_review/awaiting_contact; under_review→awaiting_contact/reviewed; awaiting_contact→under_review; reviewed→under_review with reason. Completion/reopening individual only. Bulk cap100 eligible under_review/awaiting_contact transitions, no skip/partial success. Every selected row must pass current version/state/filters under sorted header/review locks. Capture IDs/versions at preview; new requests are not silently included. One pending10minute session confirmation; same committed group replays without new events.

Individual locks immutable request header (never saves it), checks prior Owner-operation event for replay, then locks review and inserts the new event. No Customer/Cart/Catalog locks or effects. Canonical operation fingerprint binds target/kind/state/note/version/bulk; identical committed replay precedes optimistic conflict, changed payload409. New mutations need exact current version. Database unique review/request and Owner/operation plus restrictive/composite FKs are final protection. Short transactions/retry3 handle deadlocks; no claim that retries replace stale-form protection.

OwnerRequestReviewReader supplies safe list filters and detail. Detail header/review/paginated events share a REPEATABLE READ snapshot. Original IDs/quantities/flags remain visible even when Catalog is archived; no current names/prices inferred. Timeline25/page; list10/25/50, pages<=1000; identifier-only search, no contact/body scanning. Dates paired<=93days in configured app timezone, half-open UTC boundaries. Current review counts all-time; submission chart uses original creation, activity counts actual event time and distinct request count separately. Empty and missing schema differ.

Existing Customer APIs/resources/submission/replay code unchanged; internal notes never serialized there. No financial total, stock, notifications or confirmed Orders. Trusted DBAs/raw SQL remain outside append-only HTTP enforcement. Source/schema rollout must be coordinated after separate approval.
