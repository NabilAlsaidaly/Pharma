# Business settings

See [ADR024](../adr/ADR-024-business-settings-and-storefront-content.md), [approved gate](../reports/phase-06e-business-configuration-design-gate.md), [schema](../database/business-settings-schema.md), [security](../security/business-settings-security.md) and [web contract](../api/owner-business-settings-web.md).

Settings/Application/SettingGroups is the fixed configuration catalog: four explicit bounded groups with typed SQL fields, lengths, nullable semantics, domain requirements and public/preparatory meaning. ManageStoreSettings is its authorized command adapter; payment completeness lives in Settings, not Orders or the frontend. Content has its own ContentTypes and ManageStoreContent. Neither HTTP adapter accepts a table/column name or arbitrary key. A fixed allowlisted group/type selects a server-owned definition. There is no generic EAV setting editor, full configuration JSON, credentials or .env writes.

| Group | Actual fields/type | Consumer/activation |
| --- | --- | --- |
| profile | name160 required; description500/about6000; email254/phone30/address500/hours300 nullable; five fixed platform URLs500; server-only immutable raster image_path | Protected draft preview/history, explicit published configuration API; hours display only |
| currency | first_currency USD/SYP; required labels40; nullable symbols12 | Explicit published configuration API, order/labels only; no enabled currency flag/conversion |
| payment | mode full/deposit; percentage DECIMAL(5,2); nullable explanation1000 | Protected preparation/history only, never current Checkout |
| zones | name160/governorate100/optional city100; independent nullable DECIMAL(18,2)fees; sort0..999999999; conditions1000 | Protected preparation/history only; no geographic admission/fee totals |

Missing records are unconfigured, no read-time insert/default business data. Saving requires minimum valid fields, optional blank clears to null, omitted field preserves current draft. Profile publication requires name, optional logo; currency requires order and both labels. Missing public group is null, absent social links omitted. All fields have bounded strings; Arabic/Unicode accepted, dangerous controls/HTML rejected. Public social destinations match a fixed platform host list; HTTPS only, no credentials/ports/controls. No URL retrieval or remote image validation.

Current rows hold typed draft values and version; corresponding typed revision table preserves every success. Public pointer can refer to an older published snapshot while the draft changes. Published pointer and immutable revision insert are one transaction, restrictive composite FK enforces same aggregate/version. Public changes require explicit confirmed publication. Payment/delivery never acquire a public/effective pointer through the command boundary. Archive is non-destructive and restores unpublished; normalized governorate/city hash remains reserved including archive, without invented geographic overlap/fallback policy.

Shared RevisionedStore locks and revalidates the Owner, replays the canonical operation or rejects changed payload, locks target, checks version/completeness, saves draft/revision/publication pointer/event and commits. Exact payload includes target/type/action/expected-version/sorted normalized values/re-encoded image digest. String-safe unsigned BIGINT via existing Brick Math; no new dependency. Every successful action advances version; retries of the same operation do not. Request correlation and changed field names only in append-only event, long text stays in typed revisions. Trusted DBA/raw SQL immutability is outside the application boundary.

StoreReadiness uses one schema inventory query and one fixed UNION of eight aggregate queries, never loads bodies or history to count. OwnerBusinessReader paginates summaries/history25 and snapshots one detail transaction. Settings publishes its own explicit safe projection; no dependency on Content persistence reader. No cached global Boolean or Redis; see caching contract in API docs. All new writes serialize on one Owner row, a documented low-volume tradeoff. No Customer/Cart/Catalog lock or write, including no intake switch. Existing historical Checkout facts and review state remain separate.
