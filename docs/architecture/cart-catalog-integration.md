# Cart and Catalog integration

Status: IMPLEMENTED, approved additive Phase 4 boundary. `CatalogSelectionReader` is a focused Catalog Application port implemented by `EloquentCatalogSelectionReader`, bound in AppServiceProvider. Cart receives internal selection projections and evaluates them; Catalog retains authoritative prices, visibility, Variant ownership, image metadata and availability. Favorites lists reuse existing public visibility scope and ProductResource. No Catalog write workflow or public API is changed.

Bulk reads load requested Products, only selected Variants, relevant Brands and primary images. Existing CatalogStatus active semantics and AvailabilityStatus V1 `effectiveWith` rule are reused: unavailable dominates, then on_request, then available. Product price is used only without Variants; Variant pricing is exact with no fallback/range price. Decimal casts remain unchanged. Optional lock mode orders Product IDs, then Variant IDs, then Brand IDs for write admission. Cart item ordering follows after those locks. Future Catalog management must coordinate lock order and contention; no management writes are added in this phase.

Only one Catalog schema addition is authorized: `UNIQUE(id, product_id)` on product_variants, supporting composite CartItem FK `(variant_id, product_id)`. Cross-Product pairing, parent reassignment and referenced Variant deletion are rejected by MySQL; a null Variant permits a simple Product while requiring its separate Product FK. Brand model receives only an accurate CatalogStatus PHPDoc annotation for static analysis. No pricing/availability/visibility behavior change or blanket refactor.

Reads are bounded by the Cart's approved 200-selection admission cap, batched to prevent N+1 queries, with complete-Cart totals and paginated presentation. Catalog updates never modify Cart rows; current evaluation indicates accessible valid/blocked state. No old price snapshot exists, so Phase 4 cannot claim to detect a historical price difference. Current-price reevaluation is implemented; historical price-change comparison is deferred to future Checkout snapshots.

Known existing Catalog write-safety limitation: Product/Variant price ownership is enforced by model save operations and parent locks; uncontrolled raw SQL/bulk updates may bypass that cross-table business rule. Phase 4 performs no such Catalog writes. Future Business Management must address that separately, preserving the existing save/locking boundary.
