# Educational Content ownership

Phase6G extends Content under `Application/Education`, `Domain/Education`, `Infrastructure/Education` and `Interfaces/Http/Education`. [ADR026](../adr/ADR-026-educational-content-management.md) and the [approved gate](../reports/phase-06g-educational-content-design-gate.md) govern behavior. Article and Category are first-class typed aggregates; no Advice service, CMS or additions to the fixed6E ContentTypes catalog. Banners/pages/FAQs/policies retain their commands, SQL, APIs and publication behavior.

Article identity is UUIDv7/permanent unique slug, current draft version, nullable same-Article published pointer and archive state. Revisions contain bounded editorial fields, category label snapshot, structured presentation document, owner/action/time/acknowledgments. Relational revision-specific Product/Concern/source/media children prevent draft edits affecting public memberships. Category has UUID/permanent slug, current name/description/visibility/order/archive/version and immutable revisions. No hard deletion endpoints or destructive cascades.

Catalog owns Product/Brand/Concern truth. Content reads current visibility and declared Product availability, never changes Catalog. Manual links reference Product, not Variant; unavailable remains a permitted editorial reference for an otherwise visible Product. No component pricing or purchase suitability inference. Category is editorial organization, distinct from Concern. ManagementIdentity retains Owner authentication, credential/session revocation and private prefix. ManagementDashboard owns shell/navigation only. Gifts/Checkout/Cart/Settings/Payments/Delivery/System Console remain separate.

`ArticleDocument` owns the narrow schema1 validation/normalization and rendering data. `ArticleInput` validates command envelope, exact decimal string versions, fixed input fields and bounded children. Article/Category Application commands own all mutations and publication prerequisites; `EducationalStore` provides SQL readiness, actor coordination, replay, revision reconstruction and field-name-only audit. Readers expose explicit private/public projections, never generic model serialization.

No default Article/Category/source/author, no generated health advice, no diagnosis/dosage/clinical approval. Every publication needs explicit editorial_scope and review acknowledgment; health_related additionally needs at least one Owner-written source and health acknowledgment. Software verifies syntax/workflow, not clinical truth or source credibility. No public medical disclaimer is invented. No public write or Customer medical profile.
