The generic audit target is polymorphic over three fixed types; application coordinates target existence/versions, not an impossible cross-table SQL foreign key. Media files are filesystem objects with application-owned membership; no claim that UUID alone is a filesystem FK. Occasion historical labels survive edits in package/request snapshots; generic occasion audit records changed field names, not a full separate typed occasion history.

No unrestricted JSON document is authoritative for packages/requests. Only bounded audit field names use JSON. Components/images/occasions are complete relational revision sets: saving50 rows can insert50 copies per revision; this intentional storage/write amplification protects exact draft/public/history semantics and requires future retention/capacity planning. Application caps50 components/10 images/20 occasions cannot be enforced by a simple per-row CHECK, so commands validate the complete set under parent lock. Database independently enforces per-row quantity/type/relationships/uniqueness.

Primary-image CHECK explicitly requires primary_slot IS NOT NULL when is_primary=1, avoiding MySQL three-valued NULL acceptance. A real negative probe reproduced acceptance of true+NULL before this correction; the corrected constraint rejects it with3819, and a second explicit primary in the same revision is rejected with1062. Normal true/slot1 and false/NULL remain valid, including retained publication history.

History indexes include Customer/date DESC/id ASC, Owner date DESC/id ASC, currency/date DESC/id ASC to match mixed stable ordering, review state/request, audit target/time and global time, revision identity, child revision/order and media reverse lookup. Catalog existing Product/Variant/Brand indexes and physical Variant ownership remain unchanged. Explain evidence belongs in the report; no claim of production throughput.
