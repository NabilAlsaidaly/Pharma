# Owner dashboard access and privacy

Phase 6B extends [Owner access](owner-access.md) without replacing authentication. The same validated prefix, explicit owner guard, exact active role, fresh state/version,30-minute idle and production HTTPS/Secure/HttpOnly checks protect every new route. Default Customer guard and public API/visibility remain unchanged. Sidebar permissions are presentation filtering; RequireOwner is the server authority. Unknown/unsupported private paths render safe404/405 with no-store HTML, not debug traces. Generic failure rendering skips further identity lookup to avoid recursive DB failures.

Global search has four explicit business providers, safe column selection, bound SQL parameters, literal wildcard escaping, deterministic10/group limits and no secret-table scanner. No search term/contact body is added to application logs. External server/proxy/APM access logs must omit sensitive URL query values and cookies; their production policy is not independently verified. GET search terms can remain in private browser history, an operational privacy limitation.

Only aggregate Customer counts are disclosed. No Customer directory or unrestricted Customer details. Preliminary contact name/phone/email/address/notes appear solely on the protected read-only detail page with no-store. General metrics/lists/search/selection attributes exclude snapshots. Product/Variant IDs and submitted quantities/review flags are historical facts; linked current Catalog values are not presented as frozen history. All output is escaped; descriptions are plain text and no raw stored HTML is executed.

Readers perform SELECTs only. No status/payment/price/customer write, delete/restore, contact action, export, visitor tracking or hidden bulk API. Allowed profile/password changes remain Phase 6A personal account operations with CSRF/current-password revocation. Checkbox state remains transient in DOM and never enters localStorage/session/server requests. Future staff permissions must authorize each provider and destination as well as menu entries; current strict Owner middleware is not a staff implementation.

Tests positively verify actual physical sumaya_pharma_test before destructive setup and all fixtures are synthetic. Development data/schema/.env are compared by read-only row/schema hashes; no pending migration or real provisioning is authorized by this phase. Test browser server/fixtures are ignored local tooling, not public setup routes.

Production TLS/proxy/cookie domains, shared limiter/session topology, log retention, real activation and operational backups remain separate verification/approval. Analytics needs privacy/consent/event-definition/bot/retention/integration authentication decisions before collection. No invisible visitor capture is installed now. See [web contract](../api/owner-dashboard-web.md) and [architecture/scaling](../architecture/owner-dashboard.md).
