# Preliminary request management security

Reuse exact active Owner guard/RequireOwner, private validated prefix, idle and credential revocation, native CSRF/TLS/cookie rules and no-store/referrer/no-sniff headers. No new login/staff/public review API. Server derives Owner attribution, rejects unknown fields/Owner IDs. Existing shared16KiB write body cap; review mutation/preview/confirmation quota60attempts/minute/Owner on existing limiter store, including invalid/replayed attempts. Shared multi-node limits need a shared cache in a separately approved operational rollout; no Redis activation.

Strict UUID/type/version/action/status/date/pagination/note/bulk validation. Notes2000Unicode characters, no prohibited controls; HTML stored as plain text and escaped in Blade. No GET persistence or old-input flash containing note bodies. Error views show bounded generic messages, never raw SQL/fingerprints/contact/stack. Owner exception reporter logs only exception class/request correlation; no HTTP body, SQL bindings or note in ordinary logs. Infrastructure access logs must not capture bodies. Private status text never implies paid/confirmed/shipped.

PII remains original contact snapshot on protected request detail. Lists/search/pagination/overview/confirmation carry only identifiers and administrative summaries; global search never scans contact/internal notes. No hidden JS contact payload or localStorage. Customer resources remain explicit and unchanged; test non-owned404 and note non-disclosure after all review actions. Events append-only at application boundary; no erase/edit endpoint or cryptographic tamper-proof claim.

Optimistic versions, transaction-bound events, unique operation/payload identity and bounded atomic bulk protect concurrency/retry. Preview10minutes/100 explicit targets, selected membership/version/current transition rechecked; no new unseen request inclusion. Replays preserve original result before stale validation. No commercial side effects or external calls.
