# Gift security and privacy

Owner routes remain behind configured private prefix, OwnerPortalResponse, RequireOwner, native CSRF, session idle/credential/active role checks. Gift commands additionally lock/revalidate current Owner/credential before replay/mutation. Customers use existing Google-only Sanctum stateful sessions and active status middleware plus locked active-account check; no bearer tokens, recipient account or caller-supplied Customer/email authority. No production provisioning, credentials, environment editor or new admin application.

Strict top-level/nested allowlists, bounded typed text, no markup/control execution, exact Product/Variant ownership, permanent slugs, current eligibility and string versions/money protect writes. Native Owner adapters normalize canonical digit form fields explicitly; domain commands reject JSON floats/bools/strings for component quantities/order. Customer quantity/composition/price/payment/status overrides are rejected. Query filters are fixed SQL-bound values; identifiers only for request search, never recipient text or free-form SQL ordering.

GiftHttpBoundary applies no-store/private to successful Gift reads/writes and scoped API errors preserve no-store; existing Owner errors have private headers. API body16KiB, Owner nonmedia256KiB/media10MiB, source file5MiB, dimensions4096 each/pixels4194304, reencoded PNG<=8MiB. Combined form/body limits still apply even if each individual field is valid; PHP/proxy post/upload settings are separate rollout prerequisites. Public GET bodies permit empty representations only; unexpected query fields rejected. GIF animation/metadata flatten through GD. SVG/mismatch/corrupt/executable names/polyglots rejected. No remote fetch or trusted client storage path.

Private media namespace gifts/ on existing local disk; owner-only preview of retained revision membership, public SQL authorization requires currently eligible published package image. Known private/unpublished/archived/ineligible assets404; files not placed in public folder. Replaced/removed files retained for history, fresh SQL failure compensates generated file. Crash or failed cleanup can orphan bytes; trusted DBA/storage configuration is outside HTTP guarantees. Already-admitted responses cannot be recalled by later unpublication.

Gift mutation attempts share60/min/Owner, including rejected attempts/retries. Customer submissions10/hour/Customer and100/hour/IP, including rejected attempts/retries, after authentication; overflow429 with Retry-After. Customer GET uses existing personal reads quota120/min. Public reads follow existing Catalog-style infrastructure without a newly invented public business quota. Multi-instance deployments require shared limiter/session infrastructure; current file fallback is not a multi-node guarantee.

Recipient contact/address/message/sender/account email are private original facts on authenticated owned detail and authorized Owner detail only. POST/list summaries exclude them; public packages, generic audit, global search/dashboard are not expanded with PII. Private Owner notes/events never enter Customer API. Unknown and non-owned request UUIDs share404. No edit/delete/history rewriting endpoint or legal retention duration is invented.

Unexpected Owner failures log only exception class/request ID through existing private reporter. Scoped Gift API reporter `gift_http_failed` also excludes SQL bindings/stack/HTTP bodies; existing Checkout reporter preserved. Infrastructure access/error/APM logs must independently avoid request bodies and sensitive query data. Tests cover real SQL-failure rollback/redaction, native CSRF, authorization/revocation, malformed uploads, IDOR, known media URLs and real independent-connection races. Browser evidence supplements tests; full WCAG/assistive technology, external penetration testing and production capacity are not claimed.
